Pairing Proofs and Polynomial Ring Toolkit

Shramee Srivastav, MIST.cash

Build with polyring → Source on GitHub

Abstract

Elliptic curve pairings are fundamental to modern zero-knowledge proof systems, including Groth16, PLONK, and KZG polynomial commitments. In resource-constrained execution environments (Ethereum VM, BitVM, blockchain smart contracts), where computation is metered by gas fees, and in arithmetized computation systems (R1CS, Plonkish, Cairo AIR), where each computational step imposes significant prover overhead, the cost of pairing computation remains a practical bottleneck. We present a public-coin interactive proof system that consolidates the Miller loop iterations and final exponentiation into a single polynomial relation. The relation can then be verified as polynomial identities, greatly reducing the pairing costs. We present a full implementation in gnark (the industry-standard framework for arithmetized circuit development) as a reusable polynomial ring toolkit in the emulated package. Benchmarked on a 3-pairing product check (the pairing workload of a Groth16 verification), our gnark implementation achieves over 32% reduction in constraints, over 50% reduction in committed elements, and reductions in both compile-time and solver memory for both BN254 and BLS12-381 curves. This enables practical pairing verification in recursive proof systems and resource-constrained environments.

Method

One polynomial identity per Miller loop step

F(x)² · L1(x) L2(x) L3(x) = Q(x) · P12(x) + R(x)

Earlier work checks every 𝔽p12 multiplication as its own identity and commits each remainder. This work checks a whole loop step at once, then batches every step and the final exponentiation into one check at a random point. Soundness error stays below 2−244 for BN254.

F is the loop accumulator, L1 to L3 the line functions of three pairs, and P12 = x12 − 18x6 + 82 the BN254 extension modulus. Builds on El Housni, Feltroidprime, and Novakovic and Eagen's On Proving Pairings.

Paper to library

Bigger numbers, same ratio

The paper measured a bare 3-pairing check on a gnark fork. Two gnark advisories published since then, GHSA-3mvx-pp85-pm65 and GHSA-fwf3-jmp7-gmrj, added range checks to every emulated multiplication. Both columns grew, and the saving held.

The paper's fork stays frozen to reproduce its tables. polyring builds on the fixed gnark.

The toolkit

Not just pairings

The protocol ships as a toolkit for any emulated field and any monic modulus. Register a ring, submit products, and the checker proves them all with two commitments when Define returns. The paper names lattice schemes such as ML-KEM and ML-DSA as a next application.

std/polyring
prc := polyring.NewPolyRingChecker[emulated.BN254Fp](api) // before any other emulated field
modPoly := prc.MakePoly(82, 0, 0, 0, 0, 0, -18, 0, 0, 0, 0, 0, 1)
ring := prc.NewPolyRingCheck(modPoly, nil)
res, _ := prc.MulPolyRings(ring, A, B, C) // (A·B·C) mod modPoly, checked when Define returns
acc := prc.NewPolyRingAccumulator(ring, targetDeg)
acc.Mul(A).Mul(B).Sqr() // enqueue (A·B)², nothing multiplied yet
rem := acc.Eval()        // one deferred check for the whole chain
